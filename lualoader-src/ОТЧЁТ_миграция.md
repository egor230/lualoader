# Отчёт: миграция lualoader на новый plugin-sdk + Lua 5.4.9

**Дата обновления:** 13.09.2026
**Проект:** lualoader — Lua-плагин для GTA Vice City (github.com/egor230/lualoader)
**Рабочая папка:** `/mnt/807EB5FA7EB5E954/games/old GTA Vice City/lualoader-src/`
**Результат:** `lualoader.asi` (PE32, 5.3 МБ) в корне игры — Lua **5.4.9** (последняя на 13.09.2026), встроена статически.

---

## Что сделано в этот заход (поверх миграции от 24.08.2026)

1. **Lua обновлена 5.3.5 → 5.4.9** (последний релиз lua.org). Исходники в `lua/` заменены целиком на `lua-5.4.9/src`.
2. **Патчи под Lua 5.4 API** (минимальные, Lua-механика проекта не тронута):
   - `lua_resume(L, from, narg)` → `lua_resume(L, from, narg, NULL)` — в 5.4 появился 4-й параметр `int *nresults` (plugin.cpp, 5 мест);
   - из исходников Lua удалены `lua.c`, `luac.c`, `ltests.c` (имеют `main()`, ломают `-shared` линковку), оставлен `linit.c` (нужен для `luaL_openlibs`).
3. **Оригинальная структура проекта сохранена**: `plugin.cpp`, `funcs.h`, `lua/`, `build.sh` — как в предыдущей миграции; новых файлов нет кроме `Makefile` (см. ниже).
4. Промежуточная попытка разместить проект внутри `Plugin-SDK/examples/LuaLoader` **отменена по требованию** — SDK-репозиторий очищен до исходного состояния.

## Изменения Lua 5.3 → 5.4, влияющие на lualoader

| Изменение | Влияние на проект | Действие |
|---|---|---|
| `lua_resume` сигнатура `(L, from, narg, *nresults)` | не компилировалось бы | патч `NULL` 4-м аргументом |
| `main` в `lua.c`/`luac.c` | конфликт точки входа при линковке DLL | файлы исключены из сборки |
| `goto` зарезервированное слово | скрипты автора проверены `loadfile` 5.4 — все SYNTAX_OK | ничего не потребовалось |
| `lua_yieldk`/хук `LUA_MASKCOUNT` | семантика не менялась | работает как в 5.3 |
| GC: `LUA_GCCOLLECT`/`LUA_GCSTOP` | сохранены (в проекте `lua_gc(L, LUA_GCSTOP, 1)`) | без изменений |

## Сборка

```bash
cd lualoader-src
./build.sh        # или: make  (обёртка для Atom)
# результат: ../lualoader.asi — в корне игры
```

- Lua 5.4.9 (31 .c-файл) компилируется clang C11 и линкуется статически — внешние DLL не нужны;
- `objdump -p`: зависимости только KERNEL32/msvcrt/USER32;
- предупреждения линкёра «duplicate section … different size» — штатные для clang↔libstdc++ (те же при сборке SDK).

## Atom (editor AppImage + cpp-tool-bar)

Кнопка «Собрать» (F6) в Atom: пакет `cpp-tool-bar` v1.1.0 при наличии `Makefile` рядом с активным файлом запускает `make -jN` вместо одиночной g++-компиляции. Для этого в `lualoader-src/` добавлен `Makefile` (единственный новый файл, 8 строк — просто вызывает `build.sh`, структуру проекта не меняет).

Проверено: `make` из `lualoader-src` собирает и кладёт `../lualoader.asi` в корень игры.

## Проверка плагина в игре

Запустить игру (gta-vc.sh): в `lualoader/log.txt` должны появиться строки `loaded …` с текущей датой.
Старый лог от 24-08-2026 относится к Lua 5.3-версии.

## Известные ограничения (унаследованные, не менялись)

- Жёсткие адреса игры (0x869630 → заменён на `FrontEndMenuManager` SDK; 0x9B5F08 → `gGameState`; 0x974B2C → `CTimer::m_snTimeInMilliseconds`) — работает только на gta-vc.exe 1.0 EN;
- Потоковая модель (std::thread + detach) без синхронизации — как в оригинале;
- Функция `setobjоcoordes` содержит русскую «о» — историческое имя, менять нельзя (сломает существующие скрипты).
