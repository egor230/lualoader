# КАК ПЕРЕНОСИТЬ МИССИИ (памятка для ИИ)

Порядок и правила переноса миссии GTA Vice City с исходного SCM на Lua для
lualoader. Читать и соблюдать при каждой новой миссии.

## 1. Где брать исходники

Папка «Source missions» внутри игры содержит ДВА набора:

- `Sanny Builder (мод, 34 миссии)/` — переработанные версии того же набора
  миссий (проще, урезанные).
- `Оригинал игры (97 миссий)/` — полные оригинальные миссии (опкод-декод от
  reVC, с катсценами и всеми деталями).

**ВАЖНО: по номеру/названию файла нельзя определять содержание.** Пример —
«06 - Riot»: в наборе «мод, 34 миссии» это миссия про репортёра Мэла и газ,
а в «Оригинал игры (97 миссий)» — настоящий «Мятеж»: рабочие взбунтовались
на стройплощадке, надо уничтожить грузовики (SET_RIOT_INTENSITY, толпа педов,
SPAND-грузовики). ВСЕГДА проверять содержимое по коду (CREATE_CAR/CREATE_CHAR/
текст/название потока), а не по имени файла.

## 2. Порядок работы

1. Прочитать исходник целиком. Разбить мысленно на: подготовка → катсцена →
   объекты сцены → основной игровой цикл → условия успеха/провала → награда.
2. Выписать суть геймплея: какие объекты, где стоят, что делает игрок, когда
   миссия заканчивается, сколько денег даёт.
3. Сопоставить каждый нужный опкод с Lua-функцией (сверять с
   LUA_API_СПРАВОЧНИК.md и `lua_register` в plugin.cpp). Если функции нет —
   добавить в funcs.h (реализацию) + plugin.cpp (регистрацию) в стиле соседних,
   пересобрать `./build.sh`.
4. Написать миссию по каркасу (ниже). Проверить синтаксис:
   `luajit -bl "misson X.lua"` (должно закончиться без ошибок).
5. Установить в папку `lualoader/` с кодировкой UTF-8 + BOM + CRLF
   (конвертировать скриптом, как в README). Только ОДНА миссия в папке
   одновременно (см. правило 5 в разделе 4).

## 3. Каркас миссии (шаблон)

```
require("lualoader/mod")

function main()
while true do wait() local player = findplayer()
 if Star_mission_marker(9, X, Y, Z)
 then
  local step                      -- ВСЕ переменные состояния — local!
  step = nil
  set_wanted(0)
  showtext(" Миссия", 500, 1)
  ... создать сцену в темноте (SMM оставил экран чёрным) ...
  fade(1, 1200) wait(1200)        -- засветка
  printmessage("~g~Цель мисии.", 5000, 1)
  while true == Getflagmission() do wait()
   if step == nil and ... then ... step = 1 end   -- каждый этап = один шаг
   if step == 1 and ... then ... step = 2 end
   if step == 2 then ... miss(500) step = nil break end
  end
  step = nil
 end
end
end
```

- Внешний цикл: ждёт подъезда к значку НА МАШИНЕ. `Star_mission_marker` сам
  создаёт значок, высаживает игрока, убирает его авто и поднимает флаг миссии.
- Внутренний цикл: `while true == Getflagmission()` — пока миссия активна.
  Каждый этап = блок `if step == N`. В начале шага чистим старое, в конце
  меняем step. Успех — `miss(деньги)`, провал — `end_mission("mission failed!")`.
- Смерть/арест игрока обрабатывает C++-сторож `Getflagmission` (большая),
  сам снимает флаг и вызывает destroy() — очистку всех созданных объектов.

## 4. Правила переноса

1. **Координаты — инлайн.** НЕ выносить в верхний блок констант вида
   `local X, Y, Z = ...` с шапкой «-- Координаты из оригинальной миссии».
   Такой блок только засоряет код. Писать координаты прямо в месте
   использования (в вызове Createcar/Createped/ped_in_point_in_radius и т.п.).
2. **Все переменные состояния — local** (объявлять в начале блока after
   `if Star_mission_marker`). Все скрипты папки lualoader/ крутятся в потоках
   на ОБЩЕМ lua_State, поэтому глобалы разных миссий (step, blip, car...)
   пересекаются и ломают друг друга.
3. **Катсцены и спец-скины не переносятся буквально.** Полноценные катсцены
   (LOAD_CUTSCENE LAW_*) нет API — заменять коротким текстом через
   printmessage. Спец-модели (LOAD_SPECIAL_CHARACTER, спец-слоты 112/113)
   не грузятся — брать обычных педов из name_peds_list (funcs.h, карта
   «имя → модель»). Эффекты вроде SET_RIOT_INTENSITY отсутствуют — опускать,
   геймплей важнее.
4. **Модели - только по именам из списков funcs.h:**
   - Createcar("MODEL_<Название>", x, y, z) — имена в `car_model_list`
     (напр. MODEL_SPAND=213, MODEL_PONY=143).
   - Createped("<Имя>", x, y, z) — имена в `name_peds_list` (обычные педы,
     напр. HMYST, GDA) или спец-акторы в `type_specpeds_list` (IGGONZ и т.п.).
   - Оружие Giveweaponped(ped, патроны, "имя") — имена в `name_weapon_list`/
     `types_weapon_list` (molotov=тип 15, colt45=тип 17, golfclub=тип 3).
   Сверять с data/default.ide (id → имя), вызывать по имени из списков.
5. **Одна миссия в папке lualoader одновременно.** star_mission_marker в C++
   использует общие static (point/create) — две миссии будут драться за
   значок. Остальные скрипты (autoaim и диагностика) не мешают.
6. Кодировка Lua-файла: UTF-8 с BOM и CRLF. MD-документы: UTF-8 без BOM, LF.
7. Каждое имя функции проверять: оно должно быть зарегистрировано
   (`lua_register` в plugin.cpp) либо определено в mod.lua. Иначе — runtime
   ошибка в игре.

## 5. Подводные камни платформы

- `ped_frozen(0)` = управление игроком ВЫКЛЮЧЕНО (заморожен), `ped_frozen(1)` —
  включено. Именование обратное смыслу.
- `end_mission()` вызывает destroy() — чистит ВСЁ созданное миссией; свои
  переменные-указатели при этом обесцениваются — обнулять и не использовать.
- `remove_fire(id)` стирает запись из внутренней map (иначе destroy() удалит
  огонь повторно). Все remove_* гигиеничны.
- `set_current_weapon_ped(ped, тип)` — положить оружие педу в руки (01B9).
  Сначала Giveweaponped (выдать + загрузить модель), потом эта функция.
- `set_ped_stay_when_attacked(ped, true)` — пед не сходит с места при атаке
  (0350), как «бригадир» с кольтом в Riot.
- `ped_in_point_in_radius(ped, x,y,z, rx,ry,rz)` — чистое расстояние по 3D,
  работает и в машине, и пешком (внутри sleep ~10мс — не злоупотреблять
  количеством вызовов в тик).
- `iscardead(car)` — авто уничтожено (для условий «уничтожь все грузовики»).
- `getpedhealth(victim) == 0` — пед мёртв; sethealth(e,n) добавляет +0.99.
- Актуальный пример переноса «сложной» миссии: «misson riot.lua» (Мятеж:
  толпа рабочих + 3 SPAND-грузовика + 2 зачинщика с дубинами + бригадир с
  кольтом, автомат step 1→2→3).
