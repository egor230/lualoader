# Отчёт: перенос lualoader на новый plugin-sdk (v1005, коммит 15f15b60)

**Дата работы:** 15.09.2026
**Проект:** lualoader — Lua-плагин для GTA Vice City (github.com/egor230/lualoader)
**Рабочая папка:** `/mnt/807EB5FA7EB5E954/games/old GTA Vice City/lualoader-src/`
**Новый SDK:** `../Plugin-SDK` — сверён с origin/master, коммит `15f15b60` ("SA fix renderware", 08.09.2026), версия v.1005 (README_breaking_changes от 2026-08-10)
**Результат:** `../lualoader.asi` (PE32 x86 DLL, 5 337 745 Б) — сборка без ошибок, зависимости KERNEL32/msvcrt/USER32 (те же, что раньше).

## 1. Методика проверки

Старый код lualoader написан в 2021 против plugin-sdk эпохи 2018–2021 (последний
коммит старой VC-ветки — `9f1df528`, март 2018, проверено по GitHub history).
Git-история локального клона нового SDK сжата в 1 коммит (`5d7c5611`), поэтому
«8 лет изменений» сверялись тремя источниками:

1. `README_breaking_changes.md` — официальный список ломающих изменений v1001–v1005;
2. Автоматический аудит: все **192 SCM-опкода** `Command<COMMAND_…>` из funcs.h/plugin.cpp
   сверены с `eScriptCommands.h` нового SDK — **0 пропавших**;
3. Автоматический аудит: все **~80 методов и полей SDK-классов** (`->`-доступ:
   GetPosition, m_autoPilot, m_pVehicle, SetObjective, OpenDoor, m_fHealth и т.д.)
   сверены с заголовками нового SDK — **все живы**;
4. Выборочная сверка старых заголовков SDK (GitHub, коммит 2018) с новыми —
   по всем типам, которые использует lualoader.

## 2. Что реально изменилось в SDK за это время (затрагивает lualoader)

### 2.1. GetHeading() теперь возвращает РАДИАНЫ вместо градусов — главный подвох

v1004 (18.04.2026): «III, VC **CPlaceable::GetHeading()** fixed to return **Radians**
instead of degrees». В старом SDK (проверено по GitHub-архиву) метода GetHeading
в VC-ветке вообще не было; в новой версии он появился как inline в
`CEntity.h:144`: `GetHeading() { return GetForward().Heading(); }`, где
`CVector::Heading()` = `atan2(-x, y)` — радианы.

Компиляция это изменение НЕ ломает (тип тот же float), но **молча ломает поведение**:
все Lua-скрипты автора написаны под градусы (0–360). Затронуты 4 места в funcs.h:

| Место | Lua-функция | Что ломалось |
|---|---|---|
| funcs.h:1611 | `getobjangle` | Lua получал −3.14…3.14 вместо 0–360 |
| funcs.h:1630 | `getpedangle` | то же |
| funcs.h:3149 | `putincar` | радианы уходили в `COMMAND_SET_CAR_HEADING` (опкод ждёт градусы) → машина повёрнута не туда после WarpPedIntoCar |
| funcs.h:6077 | `getcarangle` | как getpedangle |

**Фикс:** во всех 4 местах чтение заменено на `GetHeading() * 57.295779f`
(радианы → градусы; 57.295779 = 180/π, та же константа, что автор использует
в своей эйлеровой математике funcs.h:8869). При этом `setcarangle`/`setpedangle`/
`setobjangle` идут через SCM-опкоды (`COMMAND_SET_*_HEADING`) и всегда работали
в градусах — теперь get/set снова симметричны, поведение 2021 года восстановлено.

### 2.2. Хардкод-адреса получили символы в новом SDK

lualoader 2021 года обращался к памяти игры по сырым адресам (работало только
на gta-vc.exe 1.0 EN). Новый SDK экспортирует все эти адреса как символы,
причём `GLOBAL_ADDRESS_BY_VERSION` даёт совместимость с 1.1/Steam бесплатно:

| Было | Стало | Примечание |
|---|---|---|
| `*(CMenuManager*)0x869630` (plugin.cpp, 2 места: `start_lualoder`, `timerstar`) | `FrontEndMenuManager` | CMenuManager.cpp:10 — тот же адрес 0x869630 |
| `patch::GetUShort(0x9B5F08)` («номер слота») | `gGameState` | CGame.cpp:22 — тот же адрес; авторская проверка `== 9` означает GS_PLAYING_GAME («в игре»), семантика сохранена |
| `patch::GetUShort(0x974B2C)` («глобальный таймер») | `CTimer::m_snTimeInMilliseconds` | CTimer.cpp:12 — адрес совпадает точно; ПОДВОХ: старый код читал **UShort** (2 байта, 0…65535 с переполнением), новый читает полный int — на сравнении `gtg < 1000` / `> 1000` (после старта игры) поведение то же, но без артефактов на 65536 мс |
| `(CCamera*)0x7E4688` (funcs.h, 5 мест) | `&TheCamera` | CCamera.cpp:15 — тот же адрес |
| `patch::GetFloat(0x7E46B8/BC/C0)` в `Getcameracoordes` | `TheCamera.GetPosition()` | 0x7E46B8 = TheCamera+0x30 = `pos` матрицы камеры (раскладка CMatrix VC не менялась с 2018: right/flags/up/pad1/at/pad2/pos/pad3 — проверено по VALIDATE_OFFSET, pos=0x30) |
| `((int(__cdecl*)(int))0x4D1E90)(wanted)` в `set_wanted` | `CWanted::SetMaximumWantedLevel(wanted)` | CWanted.cpp:82 — тот же адрес 0x4D1E90 |

Для новых символов в funcs.h добавлены 2 include (в существующий блок include'ов,
стиль сохранён): `#include "CGame.h"`, `#include "CTimer.h"`. `FrontEndMenuManager`
доступен через уже подключённый CMenuManager.h, `TheCamera` — через CCamera.h.

**Оставлены как есть** (символов в SDK нет, адреса main.scm/игры, не SDK):
`0x978748` (OnAMissionFlag — оффсет переменной main.scm в ScriptSpace; SDK даёт
только читающий метод `CTheScripts::IsPlayerOnAMission()`, а авторский код и
пишет флаг), `0x8247A8` (var_$3402 main.scm), `0x4E3690`, `0x632550`, `0x633000`,
`0x584300` (в комментарии), `0x68F5F0` (гравитация), адреса CMatrix::SetRotateX/Y/Z
(0x4DF4F0/450/3B0 — совпадают с SDK, используются напрямую, в SDK есть те же
функции, но замена потребовала бы правки логики с `(CMatrix*)car` — не трогал,
чтобы не сломать хрупкую структуру).

### 2.3. Проверено и НЕ сломалось (страховочные проверки)

Все пункты README_breaking_changes v1001–v1005 сверены с кодом lualoader:

- **v1004 enums refactor** (перемещение в enums/, `PEDTYPE_`→`PED_TYPE_`,
  удаление eVehicleModel.h): lualoader ни одного `PEDTYPE_`/`eVehicleModel` не
  использует (grep пуст) — не затронуто. Include-пути enums/ уже добавлены
  в build.sh при миграции 24.08.2026.
- **v1004 CVector2D refactor** (DotProduct→CVector2D::Dot и т.п.): в коде
  DotProduct/CrossProduct/Normalize не используются — не затронуто.
- **v1004 CPed heading unification** (`m_fMovedX/m_fMovedY`→`m_vecAnimMovingShift`,
  `m_fRotationCur`→`m_fHeadingCurrent`, `m_fRotationDest`→`m_fHeadingGoal`):
  эти поля в funcs.h/plugin.cpp не используются — не затронуто.
- **v1004 CColModel** `m_colSphere`→`m_boundSphere`: не используется.
- **v1005 CAERadioTrackManager refactor**: `set_radio` идёт через
  `COMMAND_SET_RADIO_CHANNEL` (SCM-опкод), а не через класс радио — не затронуто.
- **`m_bSirenOrAlarm` → `m_nSirenOrAlarm`** (переименование в CVehicle.h, смещение
  0x245): единственное найденное переименование, затрагивающее код — но оно уже
  было исправлено при миграции 24.08.2026 (funcs.h:3355, старое имя закомментировано).
- **v1003/v1005 переименования полей** (CAutomobile, CBike, CPhysical field_*,
  SA-ветка): все из ветки **SA**, plugin_vc не тронуты; используемые VC-поля
  (`m_autoPilot`, `m_pHandlingData`, `m_nVehicleClass`, `m_carDamage`,
  `m_vecTurnSpeed`, `m_vecFrictionTurnForce`, `m_fTotSpeed`, `m_wBombTimer`,
  `m_bHornEnabled`, `m_nCurrentGear` и др.) сверены с VALIDATE_OFFSET — живы.
- **injector.hpp фикс auto_pointer** (v.обновления 08.09.2026): lualoader
  `injector::auto_pointer` не использует — не затронуто.
- **Раскладка CMatrix VC не менялась** (right=0x0, up=0x10, at=0x20, pos=0x30,
  размер 0x48 — идентично 2018 году): весь код, работающий с `car->right/up/at/pos`
  и эйлеровой математикой (funcs.h:8849–8912), корректен без правок.
- **`m_matrix`** встречается только в закомментированном блоке (funcs.h:8079+) —
  не собирается, не проблема. В новом SDK CEntity содержит матрицу по-другому
  (через наследование CPlaceable : CMatrix), старый закомментированный код
  трогать не стал.

## 3. Дополнительный фикс: UB-краш DoorsExample

Вместе с миграцией исправлен один реальный источник крашей из старого списка
(ОТЧЁТ_lualoader.md, баг №1) — он мешал бы тестированию переноса:

`plugin.cpp`, `DoorsExample::EnableDoorEvent`: неинициализированный
`CDamageManager* p;` с разыменованием `p->GetDoorStatus(doorId)` — чтение
мусорного указателя. Исправлено на `&automobile->m_carDamage` (имя поля VC-ветки
SDK; вариант `m_pDamageManager` — это SA, в VC поле-значение `m_carDamage`,
смещение 0x2A0). Прочие известные проблемы (потоки без mutex, деструктор state,
`spite::active`, `reload()`) сознательно **не тронуты** — по требованию сохранить
хрупкую структуру кода; они не зависят от версии SDK.
